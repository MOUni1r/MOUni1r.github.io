01 · Analysis & evidence

Threshold choice changed the business trade-off.

The workflow used behavioral features, stratified train, validation, and test splits, model comparison, and threshold tuning using validation data only. The 0.223 threshold is an example operating point, not a production recommendation.

Key findingChanging the threshold made it possible to catch more potential churners, but that came with more false positives. That trade-off is the business decision the model helps expose.
02 · Model strategy

The method followed the question.

03 · Client value

What this work can help a client decide.

The model can turn a broad churn problem into a prioritized retention list, but the final threshold should come from the real cost of contacting users versus missing churners.

ProblemThe business needs to identify users worth targeting before they leave.
What the analysis addsRisk scores and threshold analysis show how many potential churners can be captured at different levels of false positives.
Practical usePrioritize outreach and test whether the intervention actually reduces churn instead of optimizing a metric in isolation.
04 · Final conclusion

The result is useful when it changes the next decision.

The main business value is not the 0.223 threshold itself. It is the ability to quantify the trade-off between catching more at-risk users and creating more false positives, then choose an operating point from real intervention costs.

What we learnedChanging the threshold made it possible to catch more potential churners, but that came with more false positives. That trade-off is the business decision the model helps expose.

05 · Recommendation & limits

What I would do next.

Recommended next steps

  • Use risk scores to prioritize outreach, then measure whether the intervention actually reduces churn.
  • Choose the operating threshold from intervention cost, capacity, and missed-churn cost using fresh data.
